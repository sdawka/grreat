# Goals Consolidate + Prioritize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the *consolidate* (DUMB-level clustering + dedupe) and *prioritize* (rank) moves to the Goals bucket of the GRREAT engine, as typed domain primitives plus two intra-workflows.

**Architecture:** Additive domain modeling. A new `aspiration` entity + `serves`/`merged-into` relations + a `rank` field extend the closed domain; two new intra-workflows (`goals-consolidate`, `goals-prioritize`) are generated by the existing `createEdgeWorkflow` factory from one `catalog.ts` entry each, with deterministic stub logic so they run offline (STUB_MODE default). No changes to the Intent schema — `INTRA_IDS` derives from the catalog.

**Tech Stack:** TypeScript, valibot, Flue (`@flue/runtime`, Cloudflare target), Durable Objects, Vitest (node suite + `cloudflare:test` workers-pool suite).

## Global Constraints

- All entity kinds are valibot schemas spread from `baseEntityFields`; the store — never the model — stamps `id`/`workspaceId`/timestamps/provenance. Mutation `data`/`patch` carry domain fields only.
- New entity kind = one schema file + one `register()` in `registry.ts`. New relation kind = one `.register()` in `relations.ts`.
- WIP limit is 5 active goals (`WIP_LIMIT`), enforced in the store on status→active. Ranking must NOT change active status.
- Adding a workflow adds a generated DO class `Flue<PascalCase>Workflow`; append a **new** uniquely-tagged migration in `wrangler.jsonc` — never edit `v1`.
- Aspirations have **no owner** (deliberately looser than goals). Merges record a decision-record AND a `merged-into` relation.
- Run `npm test` (node + workers pools) and `npm run typecheck` from `engine/`. Commit frequently.
- Commit messages: clean and concise, no attribution trailers.

```ts
/**
 * Prioritization must be a total order: two active goals should not share a
 * rank. Soft check — surfaced in admin like orphaned goals, not a write-block
 * (ranks are legitimately colliding mid-reprioritization).
 */
export function checkDuplicateRanks(goals: readonly Goal[]): ConstraintViolation[] {
  const byRank = new Map<number, string[]>();
  for (const goal of goals) {
    if (goal.status !== 'active' || goal.rank === undefined) continue;
    const ids = byRank.get(goal.rank) ?? [];
    ids.push(goal.id);
    byRank.set(goal.rank, ids);
  }
  const violations: ConstraintViolation[] = [];
  for (const [rank, ids] of byRank) {
    if (ids.length > 1) {
      violations.push({
        code: 'duplicate-rank',
        message: `Rank ${rank} is shared by ${ids.length} active goals; prioritize to break the tie.`,
        subjects: ids,
      });
    }
  }
  return violations;
}
```
